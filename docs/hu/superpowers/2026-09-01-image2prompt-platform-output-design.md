# 图片反推多平台输出设计

## 目标

调整 `huzi-image2prompt`：成功解析图片后，默认输出自然语言、GPT、Grok、Midjourney 四类 Prompt；每类均提供中文和英文版本，共八个独立代码块。任意代码块都必须一次复制、一次粘贴即可直接用于对应平台出图。

## 交互规则

1. 先读取图片并提取可见事实。
2. 仅当存在“用户能够判断、且不同答案会明显改变画面”的关键歧义时，在输出 Prompt 前只询问一个确认问题。
3. 焦段、种子、采样器、步数、CFG、具体灯具等不可从成图恢复、且用户通常无法确认的信息不询问；使用保守措辞或省略。
4. 图片不可访问时只说明阻塞原因和下一步，不输出占位 Prompt。

## 输出契约

固定顺序：

1. 自然语言 Prompt（中文）
2. Natural-language Prompt (English)
3. GPT Prompt（中文）
4. GPT Prompt (English)
5. Grok Prompt（中文）
6. Grok Prompt (English)
7. Midjourney Prompt（中文）
8. Midjourney Prompt (English)

每个代码块独立完整：包含正向视觉描述和对应平台可识别的反义提示。最终不输出“不确定项”。

## 平台适配

- **自然语言**：模型无关的完整画面描述；用自然语言写入“不要出现……”约束。
- **GPT**：以明确的生成任务句开头，完整描述画面；反义提示直接写为自然语言约束。
- **Grok**：较紧凑但完整的自然语言指令；保留关键构图和氛围；反义提示直接内嵌。
- **Midjourney**：使用描述性 Prompt，末尾添加由原图比例推导的 `--ar` 与 `--style raw`，反义提示使用 `--no`；不固定 `--v`。
- 中文与英文版本必须表达相同视觉事实；图片中的可见原文保持不变。

## 验证

使用现有真实 PNG 评估：正常图片必须输出八个代码块；每块可独立粘贴；GPT/Grok 含自然语言反义提示；Midjourney 含 `--ar`、`--style raw` 和 `--no`；最终无“不确定项”。关键歧义场景必须先询问，未确认前不生成八个 Prompt。
