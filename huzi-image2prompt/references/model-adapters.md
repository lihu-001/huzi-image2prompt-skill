# 模型感知的 Prompt 适配

在派生平台 Prompt 前使用本规范。目标是让三个平台共享同一份画面事实，同时针对其可观察到的输出偏差采用不同的编译策略。不要根据厂商训练方式做推测；只使用参考图事实、用户指定的目标信息和已有回归证据。

## 1. 建立 Canonical Visual Spec

在内部建立厂商无关的中间表示，不把它作为额外 Prompt 输出。只记录对复现有帮助的字段；不适用的字段省略：

- `canvas`：方向、宽高比、媒介、景别、裁切和留白。
- `subjects`：主体 ID、类别、数量、动作、朝向、相对位置和画面占比。需要严格复刻时可用画布宽高的近似比例描述中心点、边界或尺寸，避免虚构像素级精度。
- `geometry`：轮廓、分区、开口、交叠、附件和连接方式。
- `relations`：左右、上下、前后、包含、接触、对齐、遮挡者、被遮挡者及约略遮挡比例。关系必须落到具体对象，不能只罗列对象名称。
- `depth_layers`：从背景到前景的层级顺序，以及哪些层之间有雾、反射或透视压缩。
- `lighting_and_color`：主光方向、软硬、明暗分区、色温、主色和局部反射。
- `materials`：可见的材料、颗粒、粗糙度、光泽、厚度、褶皱、磨损或其他表面属性；平面图形不得虚构微观材质。
- `text_and_graphics`：可辨认原文、字体类别、层级、位置和对齐。
- `must_avoid`：只收录会与参考图直接冲突、且模型容易产生的结果。
- `evidence`：区分可见事实与保守推断；不得记录不可恢复的模型参数或创作者意图。

为可见事实标记复现优先级：

- `P0 identity`：一旦改变，主体身份或画面骨架就不成立，例如数量、完整轮廓、关键几何、主要遮挡、构图距离。
- `P1 similarity`：明显影响相似度，例如环境层级、主色关系、材质和次级结构。
- `P2 flexible`：允许模型合理变化，例如不可辨认纹样的具体形状、远景小物数量。

不得因为某个平台容易失败，就篡改 Canonical Visual Spec。诸如“该平台容易把建筑变对称”属于 adapter 偏差补偿，不是图片事实。

## 2. 解析目标档案

目标档案的键为：

```text
平台 / 模型（可选） / 版本（可选） / 任务类型
```

- 默认任务类型为 `reference-reconstruction`。
- 只有用户明确提供模型或版本时才使用精确档案；不得从成图猜测原始模型或版本。
- 未指定模型或版本时，使用对应平台的保守基础档案，并省略版本参数。
- 如果用户只要求一个平台或指定了某种语言，只编译该范围；Canonical Visual Spec 仍保持完整。
- 模型版本不支持或无法确认的参数一律不添加。平台档案只能控制信息排序、重复强度、语法、受支持参数和相关反义约束。

## 3. 通用编译约束

每个 adapter 都必须满足：

1. P0 全量进入正向描述，P1 在适用时进入，P2 只在不挤占 P0/P1 注意力时加入。
2. 先表达主体身份和全局构图，再表达局部细节；但具体排序由平台档案进一步调整。
3. 尺寸、位置、方向和遮挡使用关系句表达，例如“圆盘嵌在立面中，并被两条斜梁遮挡约三分之一”，不能降级为“建筑、圆盘、斜梁”的关键词列表。
4. 正向描述定义正确结果；反义约束只补偿与参考图直接冲突的高概率漂移。
5. 平台版本可以在措辞、顺序和必要的冗余上不同，但不得新增、删除或改写视觉事实。

## 4. 平台基础档案

### GPT Image

- 使用完整自然语言任务指令，把构图、空间关系、遮挡和必须保持项写成清晰句子。
- 将限制放在相关对象附近，例如描述圆盘时立即说明它是立面次级浮雕、被何物遮挡；不要依赖文末的孤立反义词列表。
- 对 P0 可适度复述一次，尤其是完整取景、非对称关系、主体数量和可见性。
- 只有参考图或已记录回归支持时，才补偿“自动美化、对称化、暖色增强、背景扩张”等偏差；不得把单次案例升级成所有图片的固定反义词。
- 不虚构平台参数。用户指定可用模型能力时才采用对应控制方式。

### Grok Imagine

- 使用紧凑、直接但语义完整的生成指令，避免文学化扩写。
- 复杂主体若容易被压缩成常规类别，明确列出不可合并的结构分区及其关系；例如分别说明左右翼、中央裂隙、嵌入圆盘、入口和基座。
- 保留从背景到前景的关键层级，避免为追求简洁而删除 P0/P1 环境关系。
- 只有参考图或回归支持时才排除“常规类别替代、单体化、结构简化”等漂移。
- 不编造 Grok 参数、模型版本或控制字段。

### Midjourney

- 使用紧凑描述性短语，并把取景距离、完整轮廓、主体占比、裁切边界和 P0 几何放在最前面。
- 容易抢占画面的局部细节必须降级说明其角色、位置和遮挡关系，例如“嵌在立面中的次级圆形浅浮雕”，然后再描述纹样。
- P1 材质和光色放在 P0 构图之后；不要让“精密纹样、发光装置、复杂铭文”等高显著词早于整体轮廓。
- 默认只附加从原图得到的 `--ar`、`--style raw` 和与参考图直接相关的 `--no`；不固定 `--v`、`--stylize`、权重或其他未请求参数。
- `--no` 不能代替正向结构描述，也不得包含会误伤正确主体的宽泛类别词。

## 5. 偏差校准

仅在用户提供跨模型对比，或仓库已有同类回归证据时记录偏差。偏差档案至少包含：

- 适用的平台、已知模型/版本和任务类型。
- 可观察的漂移，例如“全景变特写”，不要写未经证实的训练原因。
- 影响到的 P0/P1 字段和纠偏方式。
- 证据范围：单次样本、同类图片多次结果或稳定回归。

单次样本只能形成低置信度、场景相关的补偿。新结果不再出现该偏差时，应降低约束强度，避免反义提示不断累积。

## 6. 双层校验

写入 Markdown 前分别执行：

### 共享事实校验

- 每个平台版本是否保留全部 P0 和适用的 P1。
- 主体数量、位置、比例、前后层级、遮挡方向、明暗与综合色温是否一致。
- 是否把 P2 细节提升成主体，或加入图片没有的风格和对象。

### Adapter 校验

- GPT 是否使用完整关系句，并把关键限制放在对应对象附近。
- Grok 是否在保持紧凑的同时保留复杂结构分区和深度层级。
- Midjourney 是否先锁定全局构图，再写高显著局部细节，并只使用允许的保守参数。
- 未指定的模型、版本和隐藏参数是否保持未指定。

如果两层校验冲突，以共享视觉事实为准；adapter 只能调整表达，不能牺牲复现目标。
