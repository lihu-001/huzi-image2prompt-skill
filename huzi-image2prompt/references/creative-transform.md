# 受控创意变换

用户要求基于参考图做创意创作（改造、二创、风格迁移、场景置换等）时，在完成逐层观察并建立 Canonical Visual Spec 后、选择平台 adapter 前使用本规范。目标不是复现原图，而是让画面在声明的维度上产生有意变化，其余维度保持原图秩序。

## 1. 方向来源

- 用户给定方向（“换成雪夜”“变成吉卜力风格”“把主体放到火星”）时直接采用。
- 用户未给方向时，沿以下轴提出 3 个互不相同的候选方向供选择：风格媒介迁移、场景环境置换、时间天气变换、视角构图变换、色彩光线重构、叙事元素混搭。每个候选只写一句话概念和它将变换的维度，不写完整 Prompt。
- 一次只派生一个方向；用户选定后再编译平台版本。只有用户明确要求多方向对比时，才在同一份 Markdown 中输出多个方向，每个方向独立章节、独立六版。

## 2. Creative Transform Spec

选定方向后建立。以七项画像为控制维度（骨架与比例、负形与遮挡、材质、结构、可见性、构图与空间、明暗与色彩），每项必须声明一态：

- **继承**：锁定该维度，走复刻级校验；输出相对参考图漂移即失败。
- **变换**：必须按“从 X 到 Y”的映射改变；输出仍是 X，或变化内容与映射不符，即失败。
- **放开**：允许模型自由发挥；不进入必须保持清单。

Spec 字段：

```text
direction:    方向名称（2–10 字符，用于文件命名）
concept:      一句话创意概念
inherit:      [继承的画像维度]
transform:    [每个变换维度的“从 X 到 Y”映射]
free:         [放开的画像维度]
function_map: 功能接替说明：原图中承担视觉功能（重心、色彩锚点、明暗对比、叙事焦点）的元素，变换后由什么接替
canvas:       画布与比例默认继承原图；仅当方向本身要求（如横幅改竖幅）才声明变换
```

规则：

- 七个维度全部声明；未明确标记变换或放开的维度一律视为继承，不得留空。
- 继承维度沿用复刻规则：只写图片事实与保守推断，禁止虚构。虚构许可只覆盖变换和放开维度。
- 变换映射必须具体到可校验：“从雨夜巷道到雪夜巷道”要写清 X 的关键元素（雨丝、湿反射、霓虹）各自变成什么（飘雪、积雪漫反射、暖黄路灯），不能只写一个风格词。
- 功能接替必须成立：被变换元素若在原图承担最高色度锚点、视觉重心或明暗对比功能，接替者必须承担同一功能。接替关系不成立时调整变换设计，不得静默丢弃功能。
- 方向要求改变主体身份时（如“把人换成机器人”），主体相关维度标记变换并写明映射；不再按复刻模式的主体歧义规则询问，但映射必须明确。

## 3. 派生约束

- 平台编译仍走 [model-adapters.md](model-adapters.md)，任务类型为 `creative-variation`。事实源 = Canonical Visual Spec（继承维度）+ Creative Transform Spec（变换/放开维度）。
- 平台排序、画布子句、偏差补偿规则不变。变换维度按 Spec 的 Y 侧编写，继承维度按参考图编写。
- 反义提示职责不变：继承维度排除与参考图冲突的漂移；变换维度额外排除“变回 X”的结果（如雪夜方向排除雨丝、湿反射、霓虹）。
- 平台派生不得借创意名义加入方向未声明的风格、材质、物体或氛围词；变换清单之外不新增视觉事实。

## 4. 双向校验门禁

写入 Markdown 前执行：

### 继承校验

- 继承维度的 P0 和适用的 P1 全部保留；主体数量、位置、比例、遮挡方向、各颜色区排序与参考图一致——与复刻的共享事实校验相同。

### 变换校验

- 每个变换维度在所有平台版本中都确实从 X 变为 Y；仍是 X（没变）判失败。
- 变化内容与映射一致；变成映射之外的 Z（变错）判失败。
- 功能接替成立：Y 侧元素确实承担了 `function_map` 声明的视觉功能。
- 变换维度涉及文字、数量、比例等硬事实时，各平台版本之间保持一致。

## 5. 对比与纠偏

用户提供生成结果比较时：

- 先把问题分类为继承漂移（该锁没锁住）或变换不足（该变没变、变错），再按对应门禁定位。
- 纠偏纪律同复刻：每轮最多修正两个最高权重问题并锁定已正确项；继承漂移按结构优先评分定权重，变换不足以用户指出的方向意图为准。
- 自动纠偏最多三轮；不因单次失败增加跨场景永久规则。
