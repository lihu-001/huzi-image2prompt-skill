# Huzi Image2Prompt

## 核心原则

先从图片建立一份厂商无关的 Canonical Visual Spec，按骨架、比例、负形、明暗、空间、色彩标定、纹理的因果顺序形成 Reconstruction Spec，再按“平台 / 可选模型 / 可选版本 / 任务类型”选择 adapter，分别编译 GPT、Grok、Midjourney 三个平台的中英文专用 Prompt。adapter 可以改变信息排序、冗余、语法、受支持参数和偏差补偿，不能改变主体、构图、色彩或其他画面事实；每个代码块必须独立完整，一次复制、一次粘贴即可出图。每次成功生成都使用独立运行标识，将原图副本保存到 Markdown 同级的 `assets/` 并通过相对路径嵌入预览；聊天或控制台只回报实际 Markdown 路径，不重复打印完整 Prompt。

## 工作流

1. **取得图片**
   - 优先读取用户附件；也可读取可访问的本地路径或图片 URL。
   - 使用宿主已有的图片读取或视觉分析工具。不要为单次任务临时实现视觉模型。
   - 图片不存在、损坏、无权限或无法解码时，明确阻塞原因，并要求用户上传图片或提供可访问路径。看不到图片时不得输出占位 Prompt。

2. **逐层观察**
   - 画布：可靠取得的原始像素尺寸、横竖方向、目标生成比例、裁切位置、人物或主体占画面比例和留白。原始尺寸是精确元数据；目标生成比例是供生成平台使用的紧凑比例，两者不得混为一谈。
   - 主体：人物、物体、动作、表情、数量与相对位置；人物图还要记录头部朝向、视线、脸部可见程度及手机、手、头发、饰品对五官的遮挡关系。
   - 服装与造型：分别记录领口、肩部、交叉或包裹方式、衣长、腰线、开衩、拉链、链条等结构，不能只写颜色和服装类别；不得把深 V、交叉、露肩、低腰等可见结构简化成常规版型。
   - 构图：前中后景、视线方向、身体倾斜、对称或非对称、中心、对角线、俯拍或仰拍，以及手机相对脸部的位置；区分近距离随手自拍与标准居中人像。
   - 环境：地点、天气、时间和背景元素。
   - 材质与表面：将材质拆成织物或材料类型、颗粒/织纹、粗糙度、光泽度、厚度、垂坠或挺括、拉伸和褶皱。若图片能看见细微织物颗粒、低光泽或自然褶皱，必须明确写出；“真实”“黑色布料”“高细节”不能替代这些事实。
   - 光线与色彩：记录主光方向、软硬、局部高光和整体色温；对天空、主体、肤色、服装、背景、反射等主要区域分别记录色相族、相对明度与相对饱和度/色度，并标出最高和最低色度锚点。不得把中性光线任意改成明显冷蓝或暖黄氛围，也不得只写颜色名称而遗漏原图的鲜艳或克制程度。
   - 摄影语言：焦段观感、景别、机位、景深、运动感；只有画面支持时才写具体镜头词。
   - 文字与图形：逐字转录清晰文字，记录字体类别、层级、颜色、位置和对齐；不可辨认时不得补字。

3. **先确认关键歧义**
   - 仅当两个或更多解释都得到图片支持、用户能够作答、且不同答案会明显改变主体身份、文字内容、服装结构、场景类型、构图或比例时，先询问一个简洁问题。
   - 一次只问影响最大的一个关键歧义；用户回答前不要生成六个 Prompt。答案到达后继续，不再重复询问已解决事项。
   - 不询问原始模型、LoRA、种子、采样器、步数、CFG、精确焦段、灯具或后期参数。这些信息无法从成图可靠恢复，应使用保守描述或省略。
   - 若保守的可见描述足以复现画面，例如“圆形图形”而不必判断它是太阳还是装饰，则不打断用户。

4. **建立 Canonical Visual Spec 与 Reconstruction Spec**
   - 建立中间表示前必须读取 [references/reconstruction-method.md](references/reconstruction-method.md)，按其中的测量约定、六层重建顺序、色彩保真门禁、纹理门禁和 P0 硬门禁执行。
   - **可见事实**：直接保留。
   - **合理推断**：仅在有助于复现时使用“约”“类似”等保守措辞。
   - **不可恢复信息**：不得声称知道原始生成参数或创作者意图。
   - 内部中间表示至少覆盖适用的画布、主体、几何分区、对象关系、前后景层级、分区光色、材质、文字图形与直接冲突项。画布中分别保存可靠的原始尺寸和规范化目标生成比例；位置、比例、方向和遮挡必须写成对象之间的关系。严格复刻时可使用画面宽高的近似比例，不虚构局部像素级精度。
   - 把事实分为 `P0 identity`、`P1 similarity`、`P2 flexible`：P0 改变会破坏主体身份或画面骨架；P1 明显影响相似度；P2 允许合理变化。P0 必须进入所有目标 Prompt，P1 在适用时保留，P2 不得挤占 P0/P1 的注意力。
   - 默认观察顺序：媒介/风格 → 主体 → 动作与外观 → 服装/物体结构 → 环境 → 构图与裁切 → 光线与色彩 → 材质与表面 → 遮挡关系 → 镜头/景深 → 宽高比。
   - 在内部事实源中单独列出以下高漂移项，并逐项标记“必须保持”或“不适用”：
     1. **骨架与比例画像**：外轮廓、中心轴、方向、主体宽高、包围区域和身份关键锚点。
     2. **负形与遮挡画像**：主体周围和内部的空隙、开口、宽窄变化、遮挡者与约略可见比例。
     3. **材质画像**：材料类型、表面颗粒、粗糙度、光泽、厚度、褶皱与拉伸。
     4. **结构画像**：服装版型或物体几何、开口、交叠、附件及其位置。
     5. **可见性画像**：脸部或关键主体是否完整可见，哪些元素靠近但没有遮挡，哪些遮挡确实存在。
     6. **构图与空间画像**：主体占比、裁切边界、姿态、道具位置、前中后景顺序、尺度递减和空气透视。
     7. **明暗与色彩画像**：亮面、中间调、暗面、主光方向、反光强度、综合色温，以及各主要区域的色相族、相对明度、相对饱和度/色度、最高和最低色度锚点与饱和度排序。
   - 这些画像只作为内部校验，不在最终 Markdown 中增加分析章节。图片没有呈现某种微观纹理时，不得为了“更真实”而虚构颗粒、磨损或纤维。
   - P0 骨架、比例、负形与主要遮挡完整且不矛盾后，先锁定分区色相、明度和饱和度关系，再允许把铭文、裂纹、颗粒等高显著纹理编译进 Prompt。纹理不得弥补或掩盖结构错误，笼统的“克制色调”也不得压低原图定义性的高饱和区域。
   - Canonical Visual Spec 只记录图片事实和保守推断。模型容易对称化、简化、放大局部等输出偏差属于 adapter，不得混入图片事实。

5. **解析目标档案并派生六个可粘贴版本**
   - 派生前必须读取 [references/model-adapters.md](references/model-adapters.md)，按其中的中间表示、目标档案、平台基础档案和双层校验规则执行。
   - 目标档案使用“平台 / 模型（可选） / 版本（可选） / 任务类型”；默认任务为参考图复现。只有用户明确提供时才使用模型或版本信息，未指定时采用平台保守基础档案，不猜测原始模型，不添加版本参数。
   - 默认不输出“自然语言 Prompt”“通用 Prompt”或“原版 Prompt”代码块。单一视觉事实源只用于内部派生和校验，不能作为额外 Prompt 写入结果，以免用户把未适配的平台无关描述直接用于 Midjourney。
   - 将可靠的原始尺寸按 adapter 规则规范化为一个目标生成比例：仅当原图与 `1:1`、`4:5`、`16:9`、`21:9` 等常用比例的相对误差不超过 0.25% 时才采用常用比例；否则保留精确约分结果，或使用误差不超过 0.25%、两项均不大于 99 的紧凑近似。`405 × 793` 的原始尺寸保留在元数据与 GPT/Grok 尺寸参考中，目标生成比例使用接近原图的 `24:47`，不得机械输出像素式的 `--ar 405:793`，也不得强行改成不一致的常用比例。
   - **GPT**：Prompt 开头写“目标画布：[方向] [目标生成比例]；尺寸参考 [原始宽] × [原始高]”，再使用完整自然语言和明确关系句，把高漂移限制放在受影响对象附近；对有图片或回归证据的自动美化、对称化、色温或饱和度漂移做场景相关补偿。欠饱和时强化具体对象的局部色度，同时锁定其他克制区域。
   - **Grok**：Prompt 开头使用包含方向、目标生成比例和原始尺寸参考的紧凑画布子句；复杂主体容易被简化时，列出不可合并的结构分区及关系，并保留关键环境层级；调色板容易被平均化时列出颜色分区及饱和度层级，不虚构平台参数。
   - **Midjourney**：先写取景距离、完整轮廓、主体占比、裁切和 P0 几何，再写调色板定义性的高色度锚点、克制区域，最后写高显著局部细节与材质；末尾添加规范化的紧凑 `--ar [目标生成比例] --style raw` 和相关 `--no`。`--ar` 表示宽高比而非像素尺寸，不固定模型版本或其他未请求参数。
   - 三个平台均输出中文和英文。中英文表达同一视觉事实；图片中的原文保持不变，不翻译或补全。
   - 每个代码块都必须包含完整正向描述和反义提示，不能要求用户再复制第二个 Negative Prompt。正向描述负责定义正确材质和结构，反义提示只用于防止直接冲突，不能用一长串 `--no` 代替正向事实。
   - 对人物自拍，若原图主要五官完整可见，六版都要明确手机和头发不遮挡眼睛、鼻子、嘴唇或脸部轮廓，并保持原图的头部角度；若原图确有遮挡，则忠实保留，不能一律要求无遮挡。
   - 平台派生不得加入原图未呈现的风格增强词，例如“电影感”“丝网印刷”“杰作”“8K”“获奖摄影”。平台名称不是扩写画面的许可。

6. **校验并写入 Markdown**
   - 先做共享事实校验：逐版确认全部 P0、适用的 P1、对象关系、遮挡、深度层级，以及各颜色区的色相、明度、饱和度排序一致；再做 adapter 校验，确认三个平台的排序和纠偏策略确实不同。若两者冲突，以 Canonical Visual Spec 为准。
   - 六版都必须先表达骨架、比例、负形和空间，再表达高显著纹理。任何身份关键 P0 缺失或冲突都判定结构校验失败，不能用材质和装饰完整度抵消。
   - 用户提供生成结果用于对比时，使用重建规范中的结构优先评分定位误差；每轮最多修正两个最高权重误差并锁定已正确的 P0。用户明确指出的可见漂移（如饱和度不足）直接作为本轮修正目标，不被默认权重忽略。除非用户明确要求生成或连续迭代，否则只分析和重编 Prompt；自动纠偏最多三轮。
   - 六个代码块中的主体数量、左右位置、颜色、文字、目标生成比例和风格必须一致；GPT/Grok 中的尺寸参考必须等于可靠读取的原始尺寸，Midjourney 的 `--ar` 必须等于同一画布事实规范化后的紧凑比例。
   - 对照七项高漂移画像逐版检查：材质的颗粒/粗糙度/光泽不能被概括掉；服装或物体结构不能被换成常规版型；原本完整可见的脸部或关键主体不能被手机、头发、手或道具遮挡；主体占比和裁切不能从近景漂移成标准远景；综合色温不能无依据地改变；调色板定义性的高饱和区域不能变灰、褪色或被压成低色度，克制区域也不能被全局增艳。
   - 分别锁定每个主要区域的饱和度，区分正确的局部高色度与无依据的全局偏色。抑制全局偏色时不得降低原本鲜艳的区域；强化局部色度时也不得改变其他区域。反义提示不得使用会误伤正确调色板的宽泛颜色类别。
   - 反义提示只排除与当前画面直接相关的常见错误，不堆砌无关词。
   - 对照视觉事实源逐句检查，删除任何只在某个平台版本中出现、却没有图片证据的风格、材质、物体或氛围词。
   - 最终文件不输出“不确定项”章节。不可恢复信息已在生成阶段保守处理，不应增加用户复制成本。
   - 每次开始落盘时生成一个本地时间运行标识 `YYYYMMDD-HHmmss-fff`。Markdown 和本次原图副本必须共用同一个最终运行标识；即使是首次生成，也不得省略时间戳。
   - 用户指定 Markdown 目录或文件名时优先使用；缺少 `.md` 扩展名时补齐，再把运行标识插入扩展名前。例如 `result.md` 输出为 `result-20260901-150000-123.md`。
   - 用户未指定时，在当前工作目录的 `image-prompts/` 下保存。可取得原图文件名时使用 `<原图文件名（不含扩展名）>-prompts-<运行标识>.md`；仅有附件、无法取得稳定名称时使用 `image-prompt-<运行标识>.md`。
   - 在 Markdown 所在目录创建 `assets/`，将本次读取到的原图内容复制或持久化为 `assets/<原图名>-source-<同一运行标识>.<可靠扩展名>`；无稳定名称时使用 `assets/image-source-<同一运行标识>.<可靠扩展名>`。不得修改原图，不使用 Base64 数据 URI，也不把原图绝对路径写成最终图片地址。
   - 在来源元数据之后、Prompt 章节之前写入 `![原图](<assets/...>)`。链接必须相对于 Markdown 文件，路径分隔符统一为 `/`，并用尖括号包裹路径，以兼容中文、空格和常见 Markdown 特殊字符。
   - 生成名称前同时检查 Markdown 和图片副本是否已存在；若任一目标冲突，在运行标识后追加 `-001`、`-002` 等递增序号，直到两个目标都可安全创建。任何历史 Markdown 或图片副本均不得覆盖。
   - 先确保能够持久化原图副本，再写入引用它的 Markdown。图片复制、目录创建或 Markdown 写入任一步失败时，明确报错且不得声称成功；不得留下引用不存在图片的 Markdown。若 Markdown 写入失败，只可清理由本次新建且位于目标 `assets/` 内的孤立副本，不触碰历史文件。
   - 多张图片默认每张生成一个 Markdown 文件和一个对应图片副本，不能把不同图片的视觉事实写进同一组 Prompt；只有用户明确要求汇总时才写入同一文件，并为每张图片建立独立一级章节和独立图片引用。

7. **只回报落盘结果**
   - 写入成功后，聊天或控制台只简洁说明“已保存 Markdown 文件”并给出实际路径，可附带生成的平台/语言数量；不要再次打印六个 Prompt。
   - 只有用户明确要求“同时显示”“直接贴出来”时，才在保存文件后额外展示内容。
   - 如果宿主无法取得可持久化的图片内容、无法复制图片、目录不可写或 Markdown 写入失败，明确说明原因和目标路径；不要谎称已经保存，也不要静默退回仅打印 Prompt。

## Markdown 文件格式

图片成功解析且无需确认时，将以下内容写入 Markdown 文件。文件包含来源元数据，并固定使用六个可独立复制粘贴的平台专用代码块：

````markdown
# 图片反推 Prompt

> 原图：[原图文件名、附件名称或“用户附件”]
> 原始尺寸：[宽] × [高]
> 生成比例：[规范化的紧凑宽:高]

![原图](<assets/[原图名]-source-[运行标识].[扩展名]>)

## GPT Prompt

### 中文
```text
目标画布：[横向/竖向/方形] [生成比例]；尺寸参考 [原始宽] × [原始高]。请生成一张……。必须保持……。不要出现……。
```

### English
```text
Target canvas: [landscape/portrait/square] [generation ratio]; source size reference: [width] × [height]. Create an image of... Preserve... Do not include...
```

## Grok Prompt

### 中文
```text
画布：[横向/竖向/方形] [生成比例]，尺寸参考 [原始宽] × [原始高]。生成图片：……。保持……；避免……。
```

### English
```text
Canvas: [landscape/portrait/square] [generation ratio], source size reference [width] × [height]. Generate an image: ... Keep... Avoid...
```

## Midjourney Prompt

### 中文
```text
[中文描述性短语] --ar [规范化生成比例] --style raw --no [中文反义提示]
```

### English
```text
[English descriptive phrases] --ar [normalized generation ratio] --style raw --no [English negative terms]
```
````

若用户明确缩减到某个平台或某种语言，服从该范围；否则固定写入以上六版，不额外输出通用或自然语言版本。元数据中只记录能够从输入或图片读取工具可靠取得的信息；无法取得尺寸时省略原始尺寸行，GPT/Grok 不编造尺寸参考。若只能可靠判断方向或常用比例，就只写有证据的画布信息；比例也不可靠时省略生成比例行和 Midjourney `--ar`。

## 快速参考

| 场景 | 处理方式 |
|---|---|
| 存在关键歧义 | 先问一个影响最大的确认问题，回答前不输出 Prompt |
| 焦段或生成参数未知 | 不询问；使用保守措辞或省略 |
| 严格参考图复现 | 先读重建规范；依次锁定骨架、比例、负形、三值明暗、空间，最后处理纹理 |
| 用户提供生成结果比较 | 按结构优先评分找最高权重误差；每轮最多修正两个问题并锁定正确 P0 |
| 目标模型或版本未知 | 使用平台保守基础档案，不猜测，不添加版本参数 |
| GPT | 开头写方向、规范化比例和可靠的原始尺寸参考；使用完整关系句；按证据补偿漂移 |
| Grok | 开头写紧凑画布子句；复杂主体列出不可合并的结构分区和环境层级 |
| Midjourney | 全局构图和 P0 几何优先；`--ar` 只用规范化紧凑比例，不用像素尺寸 |
| 可见织物纹理 | 分别记录颗粒、粗糙度、光泽、厚度与褶皱；不能只写“真实布料” |
| 原图存在高饱和色 | 分区记录色相、明度、饱和度和相对排序；正向锁定局部色度，保持其他区域克制 |
| 生成结果颜色发灰 | 把有证据的欠饱和作为本轮目标，只强化受影响颜色区并锁定已正确结构 |
| 人物镜面自拍 | 锁定脸部可见性、头部角度、手机/头发遮挡关系、主体占比与裁切 |
| 服装或物体结构复杂 | 明确领口、交叠、开口、附件和位置，不简化为常规版型 |
| 含清晰文字 | 原样引用文字；中英文 Prompt 均不翻译图片原文 |
| 多张图片 | 默认每张图片分别生成一个 Markdown 文件，不混合视觉事实 |
| 用户未指定保存位置 | 写入当前工作目录的 `image-prompts/<图片名>-prompts-YYYYMMDD-HHmmss-fff.md` |
| 原图嵌入 | 复制到 Markdown 同级 `assets/`，使用带尖括号的相对路径 `![原图](<assets/...>)` |
| 同一图片重复生成 | 每次使用新的运行标识；冲突时追加递增序号，Markdown 与图片副本均不覆盖 |
| 文件名冲突 | 在共享运行标识后追加 `-001`、`-002` 等序号，保留已有文件 |
| 写入成功 | 控制台只返回实际文件路径，不重复打印 Prompt |
| 图片不可访问 | 说明原因与下一步，不创建占位 Markdown 文件 |

## 常见错误

| 错误 | 修正 |
|---|---|
| 单独输出 Negative Prompt | 将反义提示写入对应平台的同一代码块 |
| 输出通用/自然语言 Prompt | 默认只输出 GPT、Grok、Midjourney 三个平台中英文共六个代码块，内部视觉事实源不落为额外 Prompt |
| 六版出现不同主体或构图 | 先建立单一视觉事实源，再做平台语法转换 |
| 物体都出现但仍不像原图 | 检查宽高、锚点、负形、遮挡和尺度关系，而不是继续增加物体名或风格词 |
| 轮廓比例未通过就添加铭文和纹理 | 触发纹理门禁；先修复 P0 骨架、比例、负形和主要遮挡 |
| 用漂亮光效掩盖结构 | 先建立亮、中、暗三值体积，让光线解释结构面，再添加局部高光和氛围 |
| 只写颜色名称却没有还原鲜艳程度 | 同时写明各区域的相对明度、饱和度/色度和饱和度排序，不能只保留色相名称 |
| 抑制全局偏色时连带压低正确局部颜色 | 分区约束局部色度并锁定其他区域，不使用会误伤正确调色板的宽泛反义词 |
| 三个平台只是同一段 Prompt 换名字 | 共享 Canonical Visual Spec，但分别按目标档案调整顺序、关系表达、冗余和偏差补偿 |
| GPT/Grok Prompt 只有画面内容，没有尺寸 | 在开头写方向、规范化生成比例和可靠的原始尺寸参考 |
| 把 `405 × 793` 写成 `--ar 405:793` | 原始像素只放元数据和 GPT/Grok 尺寸参考；在保持原图比例的前提下写成紧凑近似，例如 `24:47` |
| 把模型偏差写成图片事实 | 偏差只保存在 adapter；Canonical Visual Spec 只记录可见事实和保守推断 |
| 高显著局部细节抢占画面 | 将完整取景和 P0 轮廓前置，并明确局部元素的从属结构、位置与遮挡关系 |
| 用“真实、高清、细节丰富”代替材质描述 | 写出颗粒、粗糙度、光泽、厚度、褶皱和拉伸等可见属性 |
| 可见的粗糙织物被生成成光滑缎面或塑料 | 正向写明可见织纹、粗糙度与受控光泽，并排除原图不具备的材质 |
| 人物自拍被改成手机或头发遮脸 | 明确原图的脸部可见程度、头部角度及手机/头发相对五官的位置 |
| 深 V、交叉或低腰结构被换成常规版型 | 把领口、交叠、腰线和附件作为必须保持的结构事实 |
| 近距离随手自拍被改成标准居中人像 | 锁定主体占比、身体倾斜、裁切边界和道具位置 |
| 把反义提示误称为“不确定项” | 反义提示用于排除错误；关键歧义在生成前询问 |
| 对所有未知内容都追问 | 只问用户能回答且会明显改变画面的关键歧义 |
| 为 Midjourney 固定 `--v` 或随意加参数 | 只默认添加 `--ar`、`--style raw`、`--no` |
| 自动翻译或补全图片文字 | 原样转录；不可辨认内容先确认或省略 |
| 图片不可访问仍输出占位 Prompt | 停止生成，要求可读取的图片输入 |
| 生成后仍把六版完整打印到控制台 | 默认只写入 Markdown，并在控制台回报实际路径 |
| 首次生成不带时间戳，后续才追加 | 每次都生成 `YYYYMMDD-HHmmss-fff` 运行标识，Markdown 和图片副本始终带时间戳 |
| Markdown 引用原图绝对路径或 Base64 | 将原图复制到同级 `assets/`，使用可迁移的相对路径引用 |
| 同一毫秒生成发生覆盖 | 在共享运行标识后追加递增序号，并同时检查 Markdown 与图片副本 |
| 写入失败却声称成功 | 明确报告错误和目标路径，不伪造落盘结果 |
