# Huzi Image2Prompt

## 核心原则

先从图片建立一份忠实的视觉事实，再派生自然语言、GPT、Grok、Midjourney 四类中英文 Prompt。平台适配只能改变表达和语法，不能改变主体、构图、色彩或其他画面事实；每个代码块必须独立完整，一次复制、一次粘贴即可出图。

## 工作流

1. **取得图片**
   - 优先读取用户附件；也可读取可访问的本地路径或图片 URL。
   - 使用宿主已有的图片读取或视觉分析工具。不要为单次任务临时实现视觉模型。
   - 图片不存在、损坏、无权限或无法解码时，明确阻塞原因，并要求用户上传图片或提供可访问路径。看不到图片时不得输出占位 Prompt。

2. **逐层观察**
   - 画布：横竖方向、宽高比、裁切和留白。
   - 主体：人物、物体、动作、表情、服饰、数量与相对位置。
   - 构图：前中后景、视线方向、对称、中心、对角线、俯拍或仰拍。
   - 环境：地点、天气、时间和背景元素。
   - 视觉语言：媒介、艺术风格、色板、光线、材质、纹理和细节密度。
   - 摄影语言：焦段观感、景别、机位、景深、运动感；只有画面支持时才写具体镜头词。
   - 文字与图形：逐字转录清晰文字，记录字体类别、层级、颜色、位置和对齐；不可辨认时不得补字。

3. **先确认关键歧义**
   - 仅当两个或更多解释都得到图片支持、用户能够作答、且不同答案会明显改变主体身份、文字内容、服装结构、场景类型、构图或比例时，先询问一个简洁问题。
   - 一次只问影响最大的一个关键歧义；用户回答前不要生成八个 Prompt。答案到达后继续，不再重复询问已解决事项。
   - 不询问原始模型、LoRA、种子、采样器、步数、CFG、精确焦段、灯具或后期参数。这些信息无法从成图可靠恢复，应使用保守描述或省略。
   - 若保守的可见描述足以复现画面，例如“圆形图形”而不必判断它是太阳还是装饰，则不打断用户。

4. **建立视觉事实源**
   - **可见事实**：直接保留。
   - **合理推断**：仅在有助于复现时使用“约”“类似”等保守措辞。
   - **不可恢复信息**：不得声称知道原始生成参数或创作者意图。
   - 默认顺序：媒介/风格 → 主体 → 动作与外观 → 环境 → 构图 → 光线与色彩 → 材质与细节 → 镜头/景深 → 宽高比。

5. **派生八个可粘贴版本**
   - **自然语言**：完整、模型无关的画面描述；在同一代码块末尾用“避免/不要出现”或 `Avoid` 写入反义提示。
   - **GPT**：使用明确的生成任务句，完整说明画面、构图和必须遵守的限制；用自然语言把反义提示嵌入同一代码块。
   - **Grok**：使用紧凑、直接的图片生成指令，保留全部关键视觉事实；用自然语言把反义提示嵌入同一代码块，不虚构平台参数。
   - **Midjourney**：使用描述性短语，末尾添加由原图比例约分得到的 `--ar 宽:高 --style raw`，并用 `--no` 写反义提示；不要固定 `--v`、`--stylize` 或其他未请求参数。
   - 四类均输出中文和英文。中英文表达同一视觉事实；图片中的原文保持不变，不翻译或补全。
   - 每个代码块都必须包含完整正向描述和反义提示，不能要求用户再复制第二个 Negative Prompt。
   - 平台派生不得加入原图未呈现的风格增强词，例如“电影感”“丝网印刷”“杰作”“8K”“获奖摄影”。平台名称不是扩写画面的许可。

6. **校验后输出**
   - 八个代码块中的主体数量、左右位置、颜色、文字、比例和风格必须一致。
   - 反义提示只排除与当前画面直接相关的常见错误，不堆砌无关词。
   - 对照视觉事实源逐句检查，删除任何只在某个平台版本中出现、却没有图片证据的风格、材质、物体或氛围词。
   - 最终不输出“不确定项”章节。不可恢复信息已在生成阶段保守处理，不应增加用户复制成本。

## 输出格式

图片成功解析且无需确认时，固定使用以下顺序。八个代码块都能独立复制粘贴：

````markdown
## 自然语言 Prompt

### 中文
```text
[完整中文画面描述。避免出现与该画面直接相关的错误。]
```

### English
```text
[Complete English visual description. Avoid errors directly relevant to this image.]
```

## GPT Prompt

### 中文
```text
请生成一张……。必须保持……。不要出现……。
```

### English
```text
Create an image of... Preserve... Do not include...
```

## Grok Prompt

### 中文
```text
生成图片：……。保持……；避免……。
```

### English
```text
Generate an image: ... Keep... Avoid...
```

## Midjourney Prompt

### 中文
```text
[中文描述性短语] --ar [宽:高] --style raw --no [中文反义提示]
```

### English
```text
[English descriptive phrases] --ar [width:height] --style raw --no [English negative terms]
```
````

若用户明确缩减到某个平台或某种语言，服从该范围；否则固定输出以上八版。

## 快速参考

| 场景 | 处理方式 |
|---|---|
| 存在关键歧义 | 先问一个影响最大的确认问题，回答前不输出 Prompt |
| 焦段或生成参数未知 | 不询问；使用保守措辞或省略 |
| GPT | 完整自然语言任务指令，反义提示内嵌 |
| Grok | 紧凑直接的生成指令，反义提示内嵌 |
| Midjourney | 添加 `--ar`、`--style raw`、`--no`，不固定版本号 |
| 含清晰文字 | 原样引用文字；中英文 Prompt 均不翻译图片原文 |
| 多张图片 | 每张图片分别输出一组平台 Prompt，不混合视觉事实 |
| 图片不可访问 | 说明原因与下一步，不输出八个占位代码块 |

## 示例

图片观察：横幅 16:9，米白背景上的透明玻璃香水瓶位于右侧三分之一处，左侧留白，柔和侧逆光形成浅金色高光和淡灰阴影，极简产品摄影。

平台派生示例：

````markdown
## GPT Prompt
### 中文
```text
请生成一张横幅 16:9 的极简产品摄影：米白色无缝背景，一个透明玻璃香水瓶位于画面右侧三分之一处，左侧保留大面积负空间，柔和侧逆光穿过玻璃形成浅金色高光，瓶体下方有淡灰色柔和阴影。保持干净克制的构图与细腻玻璃材质；不要出现额外物体、品牌文字、水印、强烈硬阴影或杂乱背景。
```

## Midjourney Prompt
### English
```text
minimalist product photography, transparent glass perfume bottle positioned on the right third, warm off-white seamless background, large negative space on the left, soft side backlight passing through the glass, pale golden highlights, subtle light-gray shadow, clean restrained composition, delicate glass material --ar 16:9 --style raw --no extra objects, brand text, watermark, harsh shadows, cluttered background
```
````

## 常见错误

| 错误 | 修正 |
|---|---|
| 单独输出 Negative Prompt | 将反义提示写入对应平台的同一代码块 |
| 只输出一个通用 Prompt | 默认输出四类中英文共八个代码块 |
| 八版出现不同主体或构图 | 先建立单一视觉事实源，再做平台语法转换 |
| 把反义提示误称为“不确定项” | 反义提示用于排除错误；关键歧义在生成前询问 |
| 对所有未知内容都追问 | 只问用户能回答且会明显改变画面的关键歧义 |
| 为 Midjourney 固定 `--v` 或随意加参数 | 只默认添加 `--ar`、`--style raw`、`--no` |
| 自动翻译或补全图片文字 | 原样转录；不可辨认内容先确认或省略 |
| 图片不可访问仍输出占位 Prompt | 停止生成，要求可读取的图片输入 |
